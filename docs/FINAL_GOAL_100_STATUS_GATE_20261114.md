# DATA2WEB — 최종설계 전체 100% 목표와 85점 중간 체크포인트 구분

2026-11-14 KST. 기존 사용자 승인 100점 R01~R33 가중치를 변경하거나 점수를 재계산하지 않는다. 과거 scorecard의 target_score=85는 **과거 중간 체크포인트**, 사용자의 현재 목표는 전체 100/100이다.

## 실행
- python full_goal_status.py
- python -m unittest test_full_goal_status -v
- 출력: 100점 전체 목표, 기존 85점 체크포인트, 현재 VERIFIED72/100, PENDING28/100, 미수용 R06/R07/R21/R23/R25/R26/R27/R29/R30/R32/R33, 판매 HOLD, 0원 결제, 실고객 수용·IP/라이선스·독립 외부 보안감사 미완.
- 모든 소스는 GitHub 내 원래 표준 scorecard·zero-cost 정책. **고객 파일·토큰·계좌·개인정보를 읽지 않음.**
- 인간 권리자/구매자/외부감사 증거 없이는 상태를 완료로 변경하지 않는다. 전체 100점 검증 가능해지는 시점은 **반드시 증거 검토 후 정책·scorecard를 버전 관리하며 승인**해야 한다.
- READONLY 보고서/CI 자체는 최종완성률 72를 올리지 않는다.

## 왜 별도 보고인가
A. **채택: 기존 동결된 중간 85점 계약 그대로 보존 + 별도 최종 100점 읽기전용 목표 게이트.** 기존 인증·회귀 유지, 추가 현금 지출0원, 유지보수 부담 최소.
B. 미채택: 임의로 scorecard의 동결된 85점을 100으로 교체하거나 이미 받지 않은 권리·고객/외부감사 증거를 완료로 표기. 이는 정본 변경·검증 조작이므로 금지.

오후 1시 KST 사용자의 직접 확인·계정/권리 관련사항은 기존 한 건의 예약 작업에 묶으며, 100% 목표와 현 72% 인정치를 분리 보고한다.
