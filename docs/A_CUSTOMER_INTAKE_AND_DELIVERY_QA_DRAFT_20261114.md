# DATA2WEB Studio — A안 고객 사전접수·납품 체크리스트 (초안)

**용도:** 본 문서는 형식·기능·권리 확인 단계의 **오프라인/상담 템플릿**. 실제 고객 원본/PII를 GitHub 저장소·ChatGPT·AI 자동화/웹앱·외부 도구에 넣지 않는다. 게시·자동 메신저·크몽 전송 금지(판매 GO 대기).

## 0. 고객에게 사전 요청할 최소 정보(데이터 본문 아닌 범위)
- 지원 형식: CSV / TSV / 평면 JSON / XLSX의 종류 (선택)
- 파일 개수·대략 크기(MB)·예상 행수/열수·시트명/헤더 행 위치(민감 시 공개하지 않음)
- 고객이 실제로 원할 기능: 로컬 검색/분류/정렬/상세/페이지/간단 차트/테마 선택
- 실제 자료의 권리를 소유하고 변환/결과물 제공·제3자 전달할 권한이 있는지(**고객 본인의 서면 확인 필수**)
- 필드 매핑: ID/제목/분류에 해당하는 **민감하지 않은 예시 필드명** (필드명도 민감할 수 있으니 안전 확인)
- 개인정보·민감정보·계약상 비밀·고유식별·금융/의료 자료 포함 여부 — **내용 자체는 보내지 않음**
- 결과 HTML/ZIP에 데이터 원문이 평문 포함될 수 있다는 사실 및 저장/공유 권한 확인

**권장 안내문(초안):** “고객 자료는 데이터셋/식별값 없이 형식·행열 수·가상의 예시 헤더로 먼저 검토합니다. 개인/민감/제3자 저작권 자료는 확인 전 보내지 마세요. 결과 파일은 브라우저에서 오프라인으로 열리지만 내부 데이터가 평문으로 포함될 수 있습니다. 계약 전 자료를 수신하거나 자동 업로드하지 않습니다.”

## 1. 상담 분기
| 조건 | 처리 | 자동 주문/생성 |
|---|---|---|
| CSV/TSV/평면 JSON 1개, 정본 한도 내, 권리 명확 | BASIC 제안 견적과 3열 매핑 확인 | **NO**, 가격 승인·계약 전 |
| 명시적 시트/헤더 XLSX 또는 동일 구조 다중 append | PRO/BUSINESS 후보, 원본검수/각 SHA 지정 | **NO**, 별도 스키마·권리 확인 |
| XLS/매크로 실행/PDF/OCR/SQL JOIN/로그인/실시간 호스팅/웹스크래핑 | 정본 미지원, 필요 시 별도 프로젝트 심사 | **HOLD** |
| 개인정보/의료·결제·고유식별/제3자 비밀 or 불명확한 권리 | 원본 받지 않음; 적법한 동의/권한·보호조치 확인 | **HOLD** |
| 무제한 수정/자료 구조변경/실시간 협업 요구 | 추가계약·가격/일정 별도 확인 | **HOLD** |

## 2. 승인 후에만 진행하는 로컬 작업
1. **원본은 고객이 가진 정본, 백업·권리 확인**. 승인되지 않은 자료/필드/시트가 발견되면 즉시 `HOLD`, 파일은 무단 삭제·복사하지 않음.
2. `inspect`: 원본 SHA256/크기/열/결측/중복/수식·헤더 및 승인한 시트 검수. 고객의 개인정보 내용을 공개 로그에 출력하지 않음.
3. 고객이 ID/title/category 매핑, 자료 원문 노출 위험, 개인정보 사용 여부 및 변환 권한을 명시 확인. 승인 서면을 계약/내부 보관 규칙대로 보호.
4. **새 고객 폴더명으로 create-only 생성**, 같은 폴더명이 존재하면 무덮어쓰기/중단. 고객 원본 경로/기존 출력 무수정.
5. 로컬 `verify-customer` → `verified:true`, `sale_approved:false`, HTML/ZIP/receipt SHA 등 **기술적 무결성만** 확인. 서명·법률권리 증명 아님.
6. 소유자/고객이 `index.html`을 `file://` Chrome/Edge 등 지원 브라우저로 열어 2행 이상/핵심 텍스트·검색·정렬·분류/페이징·차트·모바일·A4 인쇄 중 **요청 범위**를 시각 확인.
7. **납품자료의 사용권/적법한 권리/전송 경로/평문 안내/지원·환불·보존 정책이 명시 승인된 후** 승인된 채널로 전달. 고객이 요청하지 않은 외부 이메일/플랫폼 전달 금지.
8. 수령·하자 확인과 고객 계약에 맞는 파기/반환 책임을 별도로 기록. 고객 원본은 자동삭제하지 않음.

## 3. 고객 납품물 기대와 제한
- 파일: `index.html`, `delivery.zip`, `receipt.json`. 현재 ZIP 안에는 `index.html`, `manifest.json`, `README_KO.txt`가 들어간다. LICENSE/NOTICE 추가는 실제 허락 받은 후 verifier/migration 업데이트 전까지 불가.
- 지원 범위: 로컬 읽기형 데이터 조회/탐색; 원본 Excel 수식 재계산, 실시간 업데이트/클라우드 동기화, 개인정보 암호화, 서버 저장, 사용자 로그인/관리, PDF/OCR, 다른 데이터베이스 JOIN 제외.
- 고객 원본·실제 스크린샷·회사명/계정/개인경로는 GitHub 테스트·상품 예시로 사용 금지. 합성 예시만 허용.
- 수령 영수증의 `sale_approved:false`는 제품이 고장났다는 의미가 아니라 **상업 출시가 아직 승인되지 않았다는 현재 상태**다. 승인 전 실제 판매 납품을 진행하면 안 된다.

## 4. 증거 기록 규칙
- 코드 SHA/빌드 SHA, 테스트 종류(합성/소유자PC/외부 고객), 날짜·OS/브라우저 주요 버전, 입력 합법적 사용 동의 존재 여부, 출력 SHA/verified 상태, 민감정보 전송0 여부만 최소화해 내부 기록.
- 고객 원본 바이트/실제 행값/전체 스크린샷/개인 경로·기기 ID는 GitHub·공개 보고서·새 AI 컨텍스트에 저장하지 않는다.
- **완료와 미검증을 구별**: 코드/CI PASS ≠ 고객 구매 허가/크몽 등록/법정 동의/외부 감사. R01–R33 고정 배점/상태가 단일 기준.
